## checked
`tools/tool-proposals check mkadt|adt`: tools/mkadt.py and its tests exist (test_mkadt_*.py test the content, not the worktree setup); no proposal covers the missing `research/` symlink. tools/xrun line 74 runs `python3 -I tools/mkadt.py "$D/A.adt" --board "$board" >>"$LOG"` and ignores its output: the `warning: .../research/ipsw-x/d22ap.adt missing, no /product node` goes to xrun.log and is never read. tools/run-preflight has checks for bootargs, syntax, reach, timeout, form, cmdline, gate, root, lock, intent: none for the ADT. AP-11 (2026-10-24) was the same defect class and is only documented. TP-020 (phone-lock enforce) is unrelated except that it is the other xrun guard.

## why
Measured cost [obs]: three invalid phone runs (g111 ~8 min, g111b ~19 min, g111c ~20 min of phone time + camera), a full userdata re-flash (484 s of flash + the user's time and a wrong diagnosis), ~2 h of agent work; all avoidable by reading line 1 of xrun.log. The `research` symlink is also missing in mmio1-build, mmio-log and most other worktrees (Watcher 19, 2026-10-28), so the next run in any of them would repeat it. The only signs were an A.adt of 13364 B instead of 16048 B and `IOK SpringBoard: path IODeviceTree:/product -> none`.

## output
Three small changes, no new device access:
(a) tools/run-preflight new check `adt` (host only): `<worktree>/research/ipsw-x/d22ap.adt` must resolve (FAIL with the exact `ln -s <kernel clone>/research <worktree>/research` command); for xrun without --adt it runs `tools/mkadt.py TMP --board BOARD`, FAILs on any stdout/stderr line starting `warning:`, and FAILs when the size differs from the expected size for the board (a small table in tools/boards or a json next to it: bluejay 16048 [obs 2026-10-28, with the symlink], regenerated by the same command whenever mkadt legitimately changes; the check reports `ADT size N, expected M`).
(b) tools/xrun exits 2 right after mkadt when its output contains `warning:` unless XRUN_ALLOW_ADT_WARNING=1 (dev boards without d22ap), before any flash/build/phone access.
(c) the xrun report gets one line `ADT: <size> B, /product node present` taken from the built A.adt (decode the node list with tools/adt.py), so a bad ADT is visible in the RESULT block.
Last line stays `RESULT: PASS|FAIL|ERROR ...`; exit codes 0/1/2; details in the run dir xrun.log as today. A host test (synthetic worktree without the symlink must exit 2; with the symlink PASS) plus one mutant (drop the warning check).

## risks
None for devices (host only, before the phone lock). Risk of false FAIL when mkadt legitimately changes size: the expected-size table must be updated in the same commit as the mkadt change (the check names the table). Must never block a run silently: it always prints the fix command. No change to run-intents or phone-lock.
