## Safety (check 1) [read from source]

- magiskd has no flash step. `flash_image` appears only in scripts/uninstaller.sh:115-135 and util_functions.sh:405. `direct_install` is in app_functions.sh:61 and only the app calls it. grep of native/src/core and native/src/init for flash_image|direct_install|install_magisk finds nothing. `unlock_blocks` (core/utils.cpp:47-59) runs only through the CLI `--unlock-blocks` (magisk.rs:242).
- With /data/adb/magisk populated on boot 2, post_fs_data (bootstages.rs:112-160) runs prune, setup_magisk_env, exec_common_scripts (empty dirs on a fresh userdata), handle_modules (no modules) and clean_mounts. None of these writes a block device.
- The app still sees an incomplete environment. env_check needs magiskboot, magiskinit, util_functions.sh, boot_patch.sh and magiskpolicy (app_functions.sh:13-25), and only busybox is delivered. If the app is opened it can offer "additional setup". That runs fix_env (app_functions.sh:49-57: no flash) and then a reboot. The `ui` FORBID list (golden-pull:137, matched case-insensitively at :384) contains Reboot and Restart. Info only.
- Not introduced by this diff, but triggered on every boot: see F5 (preinit dir mkdir).
- Blocking `exec` at boot_completed. `magisk --sqlite` uses `connect_daemon(SQLITE_CMD, false)` (magisk.rs:254). If no daemon is running it fails at once with "Cannot connect to daemon" (daemon.rs:454-458) and does not spawn one. Magisk's own `--boot-complete` is the same kind of blocking exec on the same trigger (init/rootdir.rs:20-39). Keep `exec`. `exec_background` (README:614) would lose the ordering and gains nothing here.

### F3 (Medium, rule 8): su-prep cannot tell success from failure; always-FAIL `gaps=1` is the wrong contract
- File: tools/golden-pull:281-284. The only post-condition checked is that `getprop debug.pixos.bb` reads 1. That proves the property was set. It does not prove that the rc trigger fired, that the image is the unattended one at all, or that cp/mv finished.
- The run then always ends `RESULT: FAIL su-prep gaps=1` (:284 plus :438). A caller, such as the drafted `golden-su-bootstrap` (research 45 two-boot step 3), has to treat exit 1 as success. A real failure (pixos_bb denied, `cp` missing, wrong image booted) then looks identical to a good boot 1.
- Re-run semantics: AOSP README:482-483 says `property:a=b` is checked "when property a is newly created, or when the property is set to a new value". A second `su-prep` in the same boot sets 1 -> 1 and may not re-fire pixos_bb. Firing on an unchanged value is a [guess]; property_service code was not read.
- Partial delivery: if the operator reboots before the `mv`, /data/magisk holds only busybox.tmp. magiskd then adopts and deletes the dir (bootstages.rs:49-55), and boot 2 logs "Magisk environment incomplete" (:129).
- Fix (contract):
  - (a) End the service chain with `... && mv ... && rm -f /data/local/tmp/pixos_busybox && setprop debug.pixos.bb.done ok || setprop debug.pixos.bb.done fail`. Use no `$` anywhere in the rc line: init expands `${...}` (README:14-16). The magisk domain may set any property_type (rules.rs:74-80).
  - (b) su-prep runs `setprop debug.pixos.bb.done ''`, then `setprop debug.pixos.bb 0`, then `1`, so the trigger always sees a new value. It then waits ON THE DEVICE, bounded, in one `adb shell` call (for example `timeout 20 sh -c 'until [ -n "$(getprop debug.pixos.bb.done)" ]; do sleep 0.2; done'`) and reads `debug.pixos.bb.done`.
  - (c) The RESULT is PASS iff the push sha matches and done=ok. done=fail or a timeout is FAIL. Print the boot-2 instruction as a `NEXT:` line, not as a GAP.
  - (d) Move the boot-2 verification into `golden-pull su-check`. Add GAP rows for `su -c 'ls -l /data/adb/magisk/busybox'` and for `/data/magisk` still being present.
  - Real-build the rc growth against the 1276 B headroom (AP-150).

### F4 (Medium, rule 8): `magisk --sqlite` exits 0 even when the SQL fails; boot 1's grant always fails silently
- Read from source: the CLI loop returns `Ok(0)` when it reads the empty terminator (magisk.rs:253-262). `db_exec_for_cli` discards the `db_exec_with_rows` result and always writes the terminator (db.rs:320-321). init therefore logs exit 0 whatever the SQL did.
- On boot 1, the overlay rc is appended BEFORE Magisk's own rc (init/rootdir.cpp:96-104). Our exec therefore runs before `--boot-complete`, and `--boot-complete` is what first creates /data/adb (bootstages.rs:180-184). With post-fs-data aborted (:119-122), the REPLACE has no DB and is lost with no trace. That is expected on boot 1, but nothing says so.
- On boot 2, a schema or quoting error would also be invisible until `su -c id` fails.
- Fix:
  - say this in the rc comment at tools/golden-unattended-image:48 (exit status carries no information; boot 1 always fails);
  - make `golden-pull su-check` (or the F3(d) row) run `su -c "magisk --sqlite 'SELECT uid,policy,until,logging,notification FROM policies WHERE uid=2000'"` and raise a GAP unless the output is exactly `uid=2000|policy=2|until=0|logging=0|notification=0`. The format is from db.rs:308-318; Allow=2 is from lib.rs:99-103.

### F5 (Medium, rule 1, pre-existing, escalate): magiskd mkdirs a preinit dir on `sda8` at every boot_completed
- [read from source] `boot_complete` -> `setup_preinit_dir()` (bootstages.rs:186). If PREINITDEV is a block device, it finds the existing rw mount of that device and does `mkdir 0700` of `<mnt>/unencrypted/magisk | <mnt>/adb | <mnt>/watchdog/magisk | <mnt>/magisk` (core/mount.rs:20-55, base/base.cpp:396-408).
- This runs even when post-fs-data aborts: PostFsDataDone is set unconditionally (bootstages.rs:199-203, 214-219). The diff does not introduce it, and every earlier boot of this base image already ran it.
- [observed] The base image's `.backup/.magisk` says `PREINITDEVICE=sda8`. Which partition sda8 is on bluejay is recorded nowhere in the repo (grep of NOTES.md and docs found nothing). If it is persist or efs, every golden boot writes a directory into a rule-1 partition's filesystem.
- Fix (no code change in this diff): before the S0-3 run, record `ls -l /dev/block/by-name | grep -w sda8` read-only, for example in golden-pull inventory. If sda8 is not metadata, cache or userdata, park and escalate to the driver/lead before any further Magisk boot.
