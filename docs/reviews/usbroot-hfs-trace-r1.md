## Findings
F1. Low, tools/run-preflight:250-252. cfg != "DEVELOPMENT" rejects a DEBUG kernel, but the tunable is compiled `#if DEBUG || DEVELOPMENT` (pristine bsd/kern/kern_exec.c:195-197), so DEBUG would be a false FAIL (the project only builds DEVELOPMENT, xnu-local-build:615). Fix: `if cfg not in ("DEVELOPMENT", "DEBUG"):` and a test with a DEBUG_ARM64_SWEET fake kernel, or document that DEBUG is intentionally refused.
F2. Low, tools/run-preflight:221-230. kernel_config reads the file as raw; a compressed/kcache-wrapped --kernel has no VERSION string and FAILs (loud, correct direction, but the message says "not an xnu kernel?"). Probe kernels are raw Mach-O (observed kernel-usbroot-probe4.sweet). Fix: none needed; optionally append "(compressed?)" to the message.
F3. Low, 0171 hfs_vfsops.c hunk (patch ~lines 114-146): N only bounds the usbroot reads; the HFS side treats any n>0 as on and does not clamp or log N, so `sweethfstrace=1` still prints all HFS lines and a non-usbroot HFS mount traces too. Structurally bounded, so not a flood. Fix: say so in the run plan A-table (N = read count only), no code change required.
F4. Low, 0171 hfs_vfsutils.c hunks (patch ~lines 312-313 and 365): `hfsmp->scan_var` is read for the log after `hfs_unlock_mount` and before `hfs_lock_mount`, i.e. outside the mount lock; read-only, benign data race that can only mis-print. Fix: print the value inside the locked region or drop it from the format.
F5. Low, 0171 ur_strategy: reads that fail before the lock (EINVAL range, EROFS, buf_map failure, count 0) are not traced and not counted; an early failing read would be invisible in the "first N reads" list (rule 8). Fix: add one line in the `done:` path for `error && !hseq && ur_hfstrace_max` (bounded by the same cap counter), or accept and state it in the run plan.
F6. Info. Nothing is compiled (AP-147). Formats and types match by reading; -Werror=format and shadow warnings are unproven. Run tools/xnu-local-build on 23be2b7 before the slot (run plan A3 already requires it).
