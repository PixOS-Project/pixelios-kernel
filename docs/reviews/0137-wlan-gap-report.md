## Findings
1. **F1 (medium) tests**: add a host check that fails when a refusal printf loses its `swl_gap`. Fix: in shim/wlan_wr_host_test.c (or tools/test_wlan_wr_mutants.py as a sweep like glue-sweep) scan the final header and glue text for each line matching `printf\(.*(refused|not read|not touched|skipped|not implemented|STOP)` and assert the previous non-blank line contains `swl_gap(` or the line is in an explicit allowlist (:2218-equivalent). Also add one gap_report-style case per area driving a real refusal (e.g. the f2 low-window refusal in runf2) and assert `WIFI GAP: f2 ` appears in logbuf BEFORE gap_strip.
2. **F2 (low-medium) capacity**: SWL_GAP_MAX 32 < 37 static keys + dynamic STOP keys. Fix: `#define SWL_GAP_MAX 64u` (about 5.4 KB bss) and add to gap_report() a compile-time/test assertion that the number of distinct static keys fits; keep the full-table line.
3. **F3 (low) key limit**: a `what` of exactly 63 chars exists. Fix: in swl_gap() when `strlen(what) >= sizeof e->what` print the full text once with "[trunc]" (or add a host test that scans the header for any `swl_gap("` literal longer than 63 chars).
4. **F4 (low) coverage holes**: (a) wr.h `swl_w17` "halt not confirmed" path (applied :2216-2219) does not call swl_stop/swl_gap; add `swl_gap("stop", "W17 STOP: halt not confirmed", "high");` before that printf (also matches the sweet_wlan.c stage-3 error gap, so it is double counted, harmless). (b) the silent early `return`s of sweet_wlan_init after `sw_prop_is`/`sw_map` failures have no summary: add `swl_gap_summary();` before them or restructure with one exit label; also add `swl_gap("map", ...)` is already printed by sw_map, so only the summary is missing.
5. **F5 (low) tooling**: default path of KNOWN_GAPS_WIFI is user-specific. Fix: also look for `docs/KNOWN-GAPS-WIFI.md` relative to the repo root's parent or print the searched path in the "not found" line; document in the file that STOP rows are always NEW. Also fix the stale "No libc" header sentence (wr.h top) to "no libc except printf/snprintf/strcmp/memset used by swl_gap".

No finding changes a register access, store, read or branch; none is a safety issue (rule 1/2 untouched).
