## Findings

### F1 (MEDIUM) url and sha are taken from the first match in the file: a comment, a second assignment or a second fetch is silently misparsed
- tools/xnu-src-mirror:33-34. `url=$(grep -oE -m1 'https://...' | head -n 1)` and `sha=$(sed -nE 's/^...[a-z]+_sha=.../p' | head -n 1)` read the whole file, comments included.
- Failing scenario [obs, /tmp/rv/s/01-x.sh]: a stager with `# see https://example.com/docs/readme`, then `old_sha=1111...`, `new_sha=2222...`, then `git fetch https://github.com/o/a "$new_sha"` and `git fetch https://github.com/o/b "$other_sha"`. The tool answered `NOT mirrored: readme 1111111111111111111111111111111111111111` and `RESULT: PASS mirrored=0 of 1`. Wrong url (comment), wrong sha (first assignment, not the one the fetch uses), second fetch ignored, all with RESULT: PASS. Consequence: the mirror is seeded for the wrong repo/commit, the real fetch is not redirected, and the first offline build fails at the stager with "Could not resolve host", the exact AP-262 symptom. A stager that builds the url from a variable (`base=https://github.com/x; git fetch $base/hfs`) gives mirror name `x` and an insteadOf that does not match the real url; seed then fails loudly (acceptable), but only on a networked host.
- Fix: parse only the fetch call and the variable it uses: join continuation lines, strip comment lines, match `git[^|;&]* fetch[^|;&]* (https://[^ "']+) "?\$\{?([a-z_]+_sha)\}?"?`, take the sha from the `NAME_sha=` assignment of that same variable name, and `fail` when a stager has != 1 fetch call, != 1 assignment for that variable, or any `https://` token outside that call that is not a comment. Add test rows: comment url first, two `_sha=` lines, two fetches in one stager (each must be ERROR or fully covered).

### F2 (MEDIUM) the tests do not catch "wrong sha accepted" and "wrong assignment picked"
- tools/test_xnu_src_mirror.sh: no case where the remote answers with a different object than the pin, no stager with two sha lines.
- Mutants run on a copy [obs]:
  - M1: delete the seed check `[ "$(git ... rev-parse FETCH_HEAD)" = "$s" ] &&` (xnu-src-mirror:54) -> test still `RESULT: PASS cases=22`. SURVIVES.
  - M3: `head -n 1` -> `tail -n 1` on the url/sha extraction (:33-34) -> `RESULT: PASS cases=22`. SURVIVES (no stager has more than one match).
  - M2: `have` replaced by `true` in `env` (silent fallback / rewrite of a source that is not mirrored) -> 4 FAIL rows. CAUGHT.
  - M5: `have` checks HEAD instead of refs/pinned/SHA -> 8 FAIL rows. CAUGHT.
  - M6: `update-ref` failure ignored -> 1 FAIL row (seed with unreachable remote). CAUGHT.
  - New stager form (comment URL, second fetch): NOT covered (F1).
- Fix: (a) add a remote whose `git fetch URL SHA` yields a different commit (e.g. a test-only `insteadOf` mapping the pinned url to a repo that has `allowAnySHA1InWant` but where the sha is only present as another ref) and assert `seed FAILED` and no `refs/pinned/SHA`; since git itself refuses to return the wrong object for a sha, the realistic form is a test that stubs `git` on PATH with a wrapper that rewrites FETCH_HEAD, or just assert the line is present by grepping the tool text (cheapest, weaker). (b) Add the F1 stager forms; they fail the current tool and pass the fixed one.

### F3 (LOW) the integration lines in xnu-local-build have no test
- tools/xnu-local-build:552-560 (seed `|| true`, env capture, `mnames`/`mn` parse, "mirror incomplete" test, `eval "$menv"` in the stager subshell). tools/test_gate_xnu_build.py replaces the whole script with a fake, tools/test_xnu_src_mirror.sh runs only the tool. A typo in the sed parse of the NOT-mirrored line or in the `[ -z "$mnames" ] && [ -n "$mn" ] ||` condition would only show on a <offload-host> build. I read both seds against the tool's messages (xnu-src-mirror:70 and :75): they match [src].
- Fix: one host test that runs the stage_tree block against a fake stack (sourcing is hard; simpler: a `--mirror-only` or `--deps-only`-like exit is not available) or at least extract lines 552-558 into `tools/xnu-src-mirror report` printing the `say` lines, and test that.

### F4 (LOW) no lock around seed
- tools/xnu-src-mirror:47-58. Two xnu-local-build runs with different LOCALBUILD but the same ARTIFACTS (or a hand `seed` during a build) can interleave `git init --bare`/`fetch` on the same `$name.git`; both write `FETCH_HEAD`. The sha re-check prevents a wrong ref, so the failure is a loud "seed FAILED", never a silent bad tree [src]. Fix: `exec 7>>"$dir/.lock"; flock 7` around the seed loop (3 lines), or document that the build lane is single-host-serialised by heavy-job.

### F5 (LOW) relative ARTIFACTS resolves against the work tree
- tools/xnu-local-build:554 runs after `cd "$t"` (stage_tree, :543) with `--dir "$A/git-mirror"`; `dir=$(realpath -m ...)` (xnu-src-mirror:21) resolves a relative $A against the staged XNU tree, so the mirror would be created inside the build dir. [guess: ARTIFACTS is absolute everywhere in use; $HOME/pixelios-artifacts default is absolute.] Fix: in xnu-local-build, `A=$(realpath -m "$A")` once at :30.

### F6 (INFO) prefix semantics of insteadOf and mirror ownership
- `url.<mirror>.insteadOf <url>` is a prefix match, so `https://www.bearssl.org/git/BearSSL` would also rewrite `.../BearSSL-other`; no such url exists today [obs grep]. Mirrors copied to <offload-host> by rsync (tools/offload-stage-xnub, other branch) must stay owned by the container uid (`--userns=keep-id`), or git's safe.directory check refuses the local fetch [guess, not run: the <offload-host> container was not touched]. The stager would then fail loudly with "dubious ownership". Not in this diff.
