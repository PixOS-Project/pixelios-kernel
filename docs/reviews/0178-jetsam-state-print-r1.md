6. (medium, req 5) Kill-line sufficiency. The line gives memlimit_active/fatal as passed, p_memstat_memlimit_active/inactive, effective/requested priority, p_memstat_dirty, p_memstat_state, and footprint parts. It suffices to decide "never dirty/active" only with these bit tables [src]:
   - p_memstat_dirty (bsd/sys/proc.h:218-232): 0x1 P_DIRTY_TRACK, 0x2 ALLOW_IDLE_EXIT, 0x4 DEFER, 0x8 P_DIRTY (dirty now), 0x10 SHUTDOWN, 0x20 TERMINATED, 0x40 BUSY, 0x80 MARKED (was dirty before), 0x100 AGING_IN_PROGRESS, 0x200 LAUNCH_IN_PROGRESS, 0x400 DEFER_ALWAYS. "Never made dirty" = TRACK set, 0x8 and 0x80 clear.
   - p_memstat_state (bsd/sys/kern_memorystatus.h:510-531): 0x1 SUSPENDED, 0x2 FROZEN, 0x10 LOCKED, 0x20 TERMINATED, 0x80 PRIORITYUPDATED, 0x100 FOREGROUND, 0x800 MANAGED, 0x1000 INTERNAL, 0x2000 FATAL_MEMLIMIT (current), 0x4000 MEMLIMIT_ACTIVE_FATAL, 0x8000 MEMLIMIT_INACTIVE_FATAL, 0x20000 PRIORITY_ASSERTION.
   - priority values (kern_memorystatus.h:43-60,73): IDLE 0, BACKGROUND 30, FOREGROUND 100, DEFAULT 180.
   Missing: (a) whether the state is "active" per proc_jetsam_state_is_active_locked (derivable from dirty+priority but not printed; add its result, needs proc_list_lock, so skip or read racy); (b) the effective limit actually in the ledger (p_memstat_memlimit, the cached value) vs the two stored variants; (c) the kill line has no timestamp, so correlating with "limit" lines relies on order. Fix: add p->p_memstat_memlimit to the kill line (int32_t, %d), and decode hex offline with the tables above; optional: put the bit tables in the patch header.
