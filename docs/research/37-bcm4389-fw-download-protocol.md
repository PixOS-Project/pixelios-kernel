## 1. EROM pointer and walk format

### 1.1 Where the pointer is
- ChipCommon register `eromptr` at CC offset **0xFC** [src: `D/include_sbchipc.h:317` (struct field comment `/* 0xfc */`), `:652` (`#define CC_EROMPTR 0xfc`); brcmfmac same: `B/include-chipcommon.h:107`]. It holds the **backplane address** of the EROM, read as a plain 32-bit load via the BAR0 window while the window points at ChipCommon (`0x18000000`): DHD `erombase = R_REG(osh, &cc->eromptr)` [src: `D/aiutils.c:183`]; brcmfmac `read32(CORE_CC_REG(enum_base, eromptr))` [src: `B/brcmfmac-chip.c:915-916`]. ChipCommon sits at `SI_ENUM_BASE_DEFAULT = 0x18000000` [src: `D/include_hndsoc.h:43`, `D/siutils.c:246-249`; `B/brcmfmac-chip.c:1007` adds the CC core at `SI_ENUM_BASE_DEFAULT`].
- The EROM value itself is **unknown** (Unknown U1; no source states it for 4389; settled by one read of CC+0xFC).

### 1.2 How DHD points the window at it (PCI bus case)
`ai_scan` [src: `D/aiutils.c:190-197`]: `case PCI_BUS:` set `curwrap = regs + SI_CORE_SIZE`; then `OSL_PCI_WRITE_CONFIG(PCI_BAR0_WIN, 4, erombase)` (**cfg 0x80 := erombase, full value, not masked**, `:195`); `eromptr = regs` (BAR0 base). The walk limit is `eromlim = eromptr + ER_REMAPCONTROL/4` [src: `D/aiutils.c:211`], i.e. DHD assumes the whole EROM fits in the 4 KiB window it mapped (the value of `ER_REMAPCONTROL`, `ER_END`, `ER_VALID`, `ER_TAG`, `ER_CI`, `CIA_*`, `CIB_*`, `AD_*`, `SD_*`, `MPD_*`, `ER_SZ_MAX` is defined in Broadcom `aidmp.h`, which is **not in our refs**: `grep -rn ER_TAG ~/pixelios-artifacts/refs` hits only the two `.c` files [obs]). brcmfmac instead re-programs the window on every access: `addr & ~0xFFF` -> cfg 0x80, access at `addr & 0xFFF` [src: `B/brcmfmac-pcie.c:1833-1841`, `:1845-1851` (read32)], so it crosses 4 KiB pages freely. `SI_CORE_SIZE = 0x1000` [src: `D/include_hndsoc.h:64`, quoted in R36 s.3].
Both do this before any power/clock request: DHD enumerates inside `si_attach` (`D/dhd_pcie.c:2150-2181`, order in R36 s.5.1); brcmfmac `brcmf_chip_recognition` reads chipid then scans (`B/brcmfmac-chip.c:969-1027`). So the walk is plausible without PMU writes [src for the order; "plausible on this chip" is a guess until S31 runs].

### 1.3 Descriptor format (brcmfmac constants; DHD's `ER_*` names are the same hardware format but their values are not in refs)
All descriptors are 32-bit little-endian words, read in order from the EROM base [src: `B/brcmfmac-chip.c:812-829`]. Type = bits 3:0 (`DMP_DESC_TYPE_MSK 0xF`, `:21`); bit 0 = valid; word with bit 0 clear is skipped [src: `B/brcmfmac-chip.c:920-921`].
- `0x1` COMPONENT (two words: CIA then CIB, `:22-23` / `:927-936`). CIA: partnum = bits 19:8 (`DMP_COMP_PARTNUM 0x000FFF00`, `:33-34`) = the **core id** (e.g. 0x800); designer = bits 31:20 (`:31-32`). CIB: revision = bits 31:24 (`:46-47`); num slave wrappers = bits 23:19 (`:40-41`); num master wrappers = bits 18:14 (`:42-43`); num slave ports = bits 13:9 (`:44-45`); num master ports = bits 8:4 (`:48-49`).
- `0x3` MASTER_PORT (`:24`): uid bits 15:8, port number bits 7:4 (`:51-54`).
- `0x5` ADDRESS (`:25`; `(type & ~0x8) == 0x5` also matches, `:824-826`): address base = bits 31:12 (`DMP_SLAVE_ADDR_BASE 0xFFFFF000`, `:56-57`), slave-port number bits 11:8 (`:58`), kind bits 7:6 (`DMP_SLAVE_TYPE`: 0 slave, 1 bridge, 2 slave wrapper, 3 master wrapper, `:60-64`), size type bits 5:4 (0 = 4K, 1 = 8K, 2 = 16K, 3 = size descriptor follows, `:66-71`). Bit 3 (`DMP_DESC_ADDRSIZE_GT32 0x8`, `:26`) = an extra upper-32-bit address word follows [src: `B/brcmfmac-chip.c:871-875`]; a following size word (size type 3) may itself carry that bit and then has another word [src: `:877-884`].
- `0xF` EOT (end of table) [src: `B/brcmfmac-chip.c:27`, `:910` loop ends on it, `:864-869` error on unexpected EOT]. DHD's equivalent: `ent == (ER_END | ER_VALID)` ends the walk [src: `D/aiutils.c:109-110`, `:227-231`], with a bad-entry escape `ER_SZ_MAX` [src: `D/aiutils.c:116-120`].
- Walk per core, DHD [src: `D/aiutils.c:226-251`]: CIA, then CIB (must be a component-tag word, `:233-236`), then `nmp` master-port words (`:301-313`), then the **first slave ASD of port 0 = the core's register base** (`:318-338`; "should be port 0: the main register space"), further port-0 ASDs (`:340-354`), ASDs of the other slave ports (`:356-375`), then `nmw` master-wrapper ASDs (`:377-409`, must be exactly 4 KiB: `sizel == SI_CORE_SIZE`) and `nsw` slave-wrapper ASDs (`:411-440`, 4 KiB; for `nsp <= 1` the wrapper has port number 0, else 1: `fwp`, `:412`). brcmfmac's simplified rule: take the first 4K/8K slave-type address as `base` and the first wrapper-type address (master-wrapper type if the core has master ports, else slave-wrapper) as `wrapbase` [src: `B/brcmfmac-chip.c:832-901`, type choice `:840-851`, 4K/8K filter `:891-893`].
- Cores without master/slave wrappers are skipped except a list of "non-core" components that DHD keeps (PMU, GCI, SR, HUB, OOB router, CCI400, SPMI slave, NS_CCB) [src: `D/aiutils.c:273-292`]; brcmfmac keeps only cores with `nmw + nsw != 0` plus PMU and GCI [src: `B/brcmfmac-chip.c:941-946`]. Two always-skipped default-slave-wrapper components (`mfg == ARM && cid == DEF_AI_COMP`, or `nsp == 0 && nsw == 0`) [src: `D/aiutils.c:254-268`].
- Wrapper address meaning: each core has a 4 KiB **wrapper** page; its AI registers are at fixed offsets in that page: IOCTL **0x408**, RESET_CTL **0x800**, RESET_ST **0x804** [src: `B/bcma_regs.h:29,41,43`]; DHD names them `ioctrl/resetctrl/resetstatus` of `aidmp_t` (struct in `aidmp.h`, not in refs: offsets for DHD = guess that they equal the Linux ones; they are the same silicon block, "PL-368 DMP" `B/brcmfmac-chip.c:20`).

## 2. ALP clock and PMU state
- ChipCommon `clk_ctl_st` at CC+**0x1E0** (`SI_CLK_CTL_ST`) [src: `D/include_hndsoc.h:292`, struct `D/include_sbchipc.h:373`; Linux `BCMA_CLKCTLST 0x01E0`, `B/bcma_regs.h:7`]. Bits: ALP request (`CCS_ALPAREQ`) bit 3, force-ALP bit 0, force-HT bit 1, HT request bit 4, **ALP available (`CCS_ALPAVAIL`) bit 16**, HT available bit 17, "backplane on ALP" bit 18, "on HT" bit 19 [src: `D/include_hndsoc.h:296-312`; `B/bcma_regs.h:8-23`]. The PCIe core has its own copy: DHD forces ALP through `sbpcieregs_t.u.pcie2.clk_ctl_st` (`dhdpcie_force_alp`, `D/dhd_pcie.c:9954-9964`).
- What DHD does on a PCIe host: it keeps `bus->alp_only = TRUE` from attach until the ARM is released (`D/dhd_pcie.c:2146`, `:10106`) and only then sets it FALSE ("Allow HT clock now that the ARM is running", `:10349`). There is **no explicit ALP request or ALPAVAIL poll in the PCIe attach/download path**: `grep ALPAVAIL D/*.c` finds only the 4397A0 `FORCEHT`/`HTAVAIL` workaround (`D/dhd_pcie.c:2292-2300`, 4397 only) [obs grep]. brcmfmac PCIe has no ALP/clkctl code at all [obs: `grep -i "alp\|clkctl" B/brcmfmac-chip.c B/brcmfmac-pcie.c` is empty]. The clocks are requested implicitly by the wrapper `IOCTL` CLK/FGC bits when a core is reset (below) and by the SR power request (below).
- 4389 MULTIBP (SR power request): DHD requests the ARM/backplane power domain around every TCM access and around download when `MULTIBP_ENAB(sih)`: `dhd_bus_pcie_pwr_req` -> `si_srpwr_request(sih, mask, val)` with `SRPWR_DMN1_ARMBPSD_MASK` = bit 1 (or DMN0_PCIE|DMN1 if not MULTIBP) [src: `D/dhd_pcie.c:795-815`; masks `D/include_sbchipc.h:5178-5183`]. `si_srpwr_request` sets the "power on request" field `[11:8]` (`SRPWR_REQON_SHIFT 8`, `D/include_sbchipc.h:5199`) in a register at `PWRREQ_OFFSET(sih)` = `OFFSETOF(chipcregs_t, powerctl)` = **0x1E8** [src: `D/siutils.c:9280`, `D/include_sbchipc.h:375`], accessed on the PCI bus as `BAR0 + PCI_16KB0_PCIREGS_OFFSET (0x2000) + 0x1E8` (`si_corereg_pciefast_read/write`, "bar0 + 8K accesses pci/pcie core registers") [src: `D/siutils.c:9285-9306`, `D/include_pcicfg.h:652`] and spin-waits for the status field `[19:16]` (`SRPWR_STATUS_SHIFT 16`, `:5202`) [src: `D/siutils.c:9311-9361`]. `MULTIBP_CAP` sets `_multibp_enable` in `si_doattach` [src: `D/siutils.c:2824-2826`]. Whether 4389 is MULTIBP (`MULTIBP_CAP` macro body) is **not in refs** (U5); that BAR0+0x2000 is a fixed alias of the PCIe core (and BAR0+0x3000 of ChipCommon, `D/include_pcicfg.h:653`, used by DHD's fast path `D/aiutils.c` `ai_corereg_addr`, "Chipc registers are mapped at 12KB", conditional on `SI_FAST`) is a DHD behaviour for PCIe Gen2 chips whose BAR0 maps 32 KiB (`D/include_pcicfg.h:638`); **[guess]** it holds for the 4389, and R36's `0x18001000` reset window (slot 1) is consistent with fixed slots 0x2000/0x3000 being separate. Settle by reading BAR0+0x3000 (expect the chip id word) in S31 run A. This is the one "power" write that DHD does before touching RAM/ARM; brcmfmac has none.
- ChipCommon PMU registers live in the CC page: `pmucontrol` 0x600, `pmustatus` 0x608, `min_res_mask` 0x618, `max_res_mask` 0x61C [src: `D/include_sbchipc.h:55-62` (this is the PMU view of struct; the CC-struct copy is `:429-436`)]. Reading them is allowed in a read-only step; writing them is not planned (DHD does it only in the 4397A0 WAR, `D/dhd_pcie.c:2285-2300`).

## 3. ARM core halt/reset sequence
DHD `dhdpcie_bus_download_state(bus, TRUE)` [src: `D/dhd_pcie.c:10071-10376`, enter branch `:10099-10175`], CA7 case (4389) [src: `:10123-10134`]:
1. `dhdpcie_setbar1win(bus, 0)` = **cfg 0x84 (`PCI_BAR1_WIN`) := 0** so BAR2 (= DHD "BAR1") maps backplane 0 [src: `:10105`, `D/dhd_pcie.c:6193-6197`, cfg 0x84 `D/include_pcicfg.h:489`]; `alp_only = TRUE` (`:10106`).
2. select the ARM core (`si_setcore(ARMCA7_CORE_ID)`, `:10123`) = write cfg 0x80 := its register base and cfg 0x70 := its wrapper base [src: `D/aiutils.c:555-587` (PCI_BUS case: `PCI_BAR0_WIN` := addr, `PCIE2_BAR0_WIN2` := wrap); wrapper reached at BAR0+0x1000 = `curwrap`, `D/aiutils.c:192`, `SI_CORE_SIZE`].
3. `si_core_reset(sih, SICF_CPUHALT, SICF_CPUHALT)` on the CA7 (`:10125`) = `ai_core_reset(bits=CPUHALT, resetbits=CPUHALT)` [src: `D/aiutils.c:1328-1347` -> `_ai_core_reset` `:1242-1317`]. Steps of `_ai_core_reset` on the wrapper [src: `D/aiutils.c:1242-1317`]: spin-wait RESET_ST == 0 (300 us); write RESET_CTL := `AIRC_RESET` (bit 0 [src: `B/bcma_regs.h:42`]); delay 10 us; wait RESET_ST == 0; write IOCTL := `bits | resetbits | SICF_FGC | SICF_CLOCK_EN` (FGC = 0x2, CLOCK_EN = 0x1, `D/include_hndsoc.h:266-267`); read back; wait RESET_ST == 0; up to 10 times: wait RESET_ST == 0, write RESET_CTL := 0 (leave reset), wait; finally write IOCTL := `bits | SICF_CLOCK_EN` (so FGC drops, CPUHALT stays), read back, delay 1 us. Result: **ARM out of reset but held halted** (IOCTL.CPUHALT set).
   - `SICF_CPUHALT` itself is not defined in the refs (`grep SICF_CPUHALT D/include_*.h` is empty [obs]); brcmfmac uses `ARMCR4_BCMA_IOCTL_CPUHALT = 0x0020` for both CR4 and CA7 [src: `B/brcmfmac-chip.c:78`, used at `:1073-1075`, `:1331`, `:1358`]. DHD value = **[guess] 0x20**.
   - brcmfmac equivalent: `brcmf_chip_disable_arm` clears all IOCTL bits except HALT then `resetcore(prereset=val, reset=HALT, postreset=HALT)` [src: `B/brcmfmac-chip.c:1052-1081`]; `ai_resetcore` = `coredisable` (RESET_CTL := 1, wait, IOCTL := reset|FGC|CLK) then loop RESET_CTL := 0 up to 50 times, then IOCTL := postreset|CLK [src: `B/brcmfmac-chip.c:350-382`, `:434-492`]. CA7 passive also resets D11 with PHYRESET|PHYCLOCKEN flags (`ca7_set_passive`, `:1337-1348`; D11 flag bits `:81-82` = 0x4, 0x8); **DHD does not touch D11 on enter** (no D11 access in `:10099-10175`) [src]. Guess: D11 is brought up by the firmware.
4. `si_setcore(SYSMEM_CORE_ID)`; `si_core_reset(sih, 0, 0)` = reset+enable the RAM core (`:10126-10131`).
5. `dhdpcie_init_shared_addr`: write 0 to the last RAM word `dongle_ram_base + ramsize - 4` (`:10133`, `D/dhd_pcie.c:14335-14343`). The firmware overwrites this word with the shared-area pointer once running (see s.7).
Pre-step in attach (not in download): `dhdpcie_dongle_reset` = FLR via PCIe config or ChipCommon watchdog reset (`pcie_watchdog_reset`) [src: `D/dhd_pcie.c:1741-1780`; called from attach when `dongle_reset_needed` (`:2269`) at `:2323-2324`]; whether we need it after a fresh PERST is **U7** (the chip was just power-cycled by the shim; DHD "EFI requirement" check that the ARM is halted is compiled to `return TRUE` outside EFI, `D/dhd_pcie.h:903`).
CA7 coherency: for `ARMCA7_CORE_ID` DHD ORs `PCIE_BARCOHERENTACCEN_MASK` (0x300) into cfg **0x88** (`PCIE_CFG_SUBSYSTEM_CONTROL`) before download [src: `D/dhd_pcie.c:2223-2228`, `D/include_pcicfg.h:491,586`]. Cfg 0x88 was observed `0x00080080` (R36 s.0): **a new cfg write**, only needed if the CA7 needs coherent BAR access; U8.

## 4. RAM base and size for 4389; TCM access over BAR2
- Base: `bus->dongle_ram_base = CA7_4389_RAM_BASE = 0x200000` for chip 4388/4389 in the SYSMEM branch [src: `D/dhd_pcie.c:2340-2353`, `D/include_sbchipc.h:4169`]. brcmfmac's table has no 4389; 4387 = 0x740000 (a different part) [src: `B/brcmfmac-chip.c:746-747`] - do not use it.
- Size: **not a constant**; it is read from the SYSMEM core: `si_sysmem_size` [src: `D/siutils.c:6988-7061`]: core must be up (it resets it if not, `:7016-7024` = a write), read `coreinfo`, number of RAM banks `nb` (field layout depends on `si_corerev`: `<12` old masks, `>=12` `SYSMEM_SRCI_NEW_*`; the mask values are in `sbsysmem.h`, not in refs), then for each bank write `bankidx`, wait 10 us (`SI_BANKINFO_DELAY_USEC`, `:6961`), read `bankinfo`, `banksize = SYSMEM_BANKINFO_SZBASE * ((bankinfo & SZMASK) + 1)` [src: `D/siutils.c:6966-6980`]. brcmfmac's version of the same read (same register block as SOCRAM): coreinfo at +0x00, bankidx at +0x10, bankinfo at +0x40; banksize = ((bankinfo & 0x7F) + 1) * 8192; `nb = (coreinfo & 0xF0) >> 4` [src: `B/brcmfmac-chip.c:165-201` (struct, offsets by counting fields: coreinfo 0, bwalloc 4, extracoreinfo 8, biststat 0xC, bankidx 0x10, standbyctrl 0x14, errlogstatus 0x18, errlogaddr 0x1C, cambank* 0x20-0x38, PAD 0x3C, bankinfo 0x40), `:145-155,:583-591,:657-676`]; DHD's `sysmemregs_t` is **not** in refs (U3), and the new-rev masks differ, so the brcmfmac offsets are a [guess] for 4389.
- DHD limits: `ramsize > DONGLE_TCM_MAP_SIZE` (4 MiB, `D/dhd_pcie.h:42`) is an attach failure [src: `D/dhd_pcie.c:2453-2457`]; brcmfmac also caps at 4 MiB [src: `B/brcmfmac-chip.c:84`, `:795-798`]. RAM spans backplane `0x200000 .. 0x200000 + ramsize - 1` [src: `D/dhd_pcie.c:6164-6167`]. Our BAR2 is exactly 4 MiB [obs R28]; if `ramsize > 2 MiB` the RAM end passes backplane 0x400000 and DHD's `bar1_switch_enab` makes it move the window per access [src: `D/dhd_pcie.c:6162-6181`; mapping `DHD_BUS_BAR1_BPWIN(addr, size) = addr & ~(size-1)`, `:6149-6151`]. (So on 4389 a firmware at `0x200000` needs cfg 0x84 = 0 for the first 2 MiB and = 0x400000 for the rest.)
- Access path: DHD `bar1` = PCI resource **2** mapped >= 4 MiB (`D/dhd_pcie_linux.c:1951-1967`), TCM accessor `dhdpcie_bus_wtcm32(bus, backplane_addr, v)`: `offset = addr - bpwin` after `bpwin = addr & ~(bar1_size-1)` and, if `bpwin != curr_bar1_win`, write cfg 0x84 := bpwin [src: `D/dhd_pcie.c:6210-6235`, and `wtcm8` use `:6238-6255`]. Writes are 64-bit if `DHD_SUPPORT_64BIT` else 32-bit when 4-byte aligned and size >= 4, else byte [src: `D/dhd_pcie.c:5651-5675`]; brcmfmac uses `memcpy_toio` / `iowrite32` at `tcm + rambase + off` [src: `B/brcmfmac-pcie.c:1700,561-575`].
- For our shim: CPU address of backplane A (with cfg 0x84 = W) = `0x60400000 + (A - W)`. Needs a **new outbound iATU region covering BAR2** (R36 s.2: region 1 covers only BAR0, 64 KiB). ## 5. Firmware download (TCM), NVRAM tail and length token

## 7. After release: handshake and shared-area discovery
- Poll the **last RAM word** `shaddr = dongle_ram_base + ramsize - 4` (the same word that held the NVRAM length token): `while ((addr == 0 || addr == bus->nvram_csm) && !timeout) addr = LE32(read(shaddr))` [src: `D/dhd_pcie.c:13613`, `:13641-13651`; `MAX_READ_TIMEOUT` value not read: DHD comment says 5 seconds]. The firmware replaces the token with the **address of `pciedev_shared_t`** in dongle RAM. brcmfmac: write 0 to the word before release, then poll every 50 ms for up to 5000 ms (`BRCMF_PCIE_FW_UP_TIMEOUT`) until it changes [src: `B/brcmfmac-pcie.c:1709-1711,1740-1768`, `:113`]. (brcmfmac writes 0 to `ramsize - 4` *before* the NVRAM; DHD writes the token there at the end; both are "unchanged until the firmware writes it".)
- Validity rules: `0xFFFFFFFF` = link/read failure; `addr == 0`, `addr == nvram_csm`, `addr < dongle_ram_base` or `addr > shaddr` = "dongle is not ready" (and DHD then logs CA7 `AI_IOCTRL`/`AI_RESETCTRL`) [src: `D/dhd_pcie.c:13654-13705`]; brcmfmac range check `rambase <= addr < rambase + ramsize` [src: `B/brcmfmac-pcie.c:1764-1770`].
- Then DHD reads `sizeof(pciedev_shared_t)` bytes at `addr` (`:13730-13732`), little-endian fixups for `flags, trap_addr, assert_exp_addr, assert_file_addr, assert_line, console_addr, msgtrace_addr, dma_rxoffset, rings_info_ptr, flags2` (`:13737-13746`); `console_addr` = the firmware console ring (for a read-only log of firmware boot messages), `flags & PCIE_SHARED_VERSION_MASK` = protocol version (`:13755`; brcmfmac `BRCMF_PCIE_SHARED_VERSION_MASK 0xFF`, max 7: `B/brcmfmac-pcie.c:212-215`). The struct layout/offsets are in `dhd_pcie.h`/`bcmpcie.h`; I did not extract them this session (U13) - not needed for "alive" detection, which is just step 1 of this section.
- After this DHD proceeds to rings/mailbox (`dhd_bus_init`), which is XNU-side driver work (coverage D2), not the shim.
