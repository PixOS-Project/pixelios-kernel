## 1. Findings that change the plan (each cited below)
1. **4389 is MULTIBP, so DHD requests the ARM/WL backplane power domain before it touches the ARM or SYS_MEM wrapper.** `MULTIBP_CAP` lists `BCM4389_CHIP` [src: `G/g4389-include_siutils.h:963-968`], attach sets `_multibp_enable` [src: `G/g4389-siutils.c:2830-2832`], the header comment says WL backplane (ARM, TCM) "Host needs to power up" [src: `G/g4389-include_siutils.h:955-962`]. Closes **U5** (research 37/38). The request is `si_srpwr_request(sih, 0x2, 0x2)` [src: `D/dhd_pcie.c:795-816`] called before the first `si_setcore(ARMCA7)` [src: `D/dhd_pcie.c:2203-2205`, `:2211-2215`].
2. **CPUHALT = 0x20** in DHD too: `#define SICF_CPUHALT (0x0020)` [src: `G/g4389-include_siutils.h:306`; same in `G/seemoo-siutils.h:148`, `G/whd_chip.h:37`], brcmfmac `ARMCR4_BCMA_IOCTL_CPUHALT 0x0020` used for CA7 [src: `B/brcmfmac-chip.c:78`, `:1067-1075`, `:1358`]. DHD calls `si_core_reset(sih, SICF_CPUHALT, SICF_CPUHALT)` on the CA7 [src: `D/dhd_pcie.c:10123-10125`]. Closes the "DHD value is a guess" point of research 37 s.3 / 38 U7. That the bit really halts a 4389 CA7 is verified only by the IOCTL read-back (value `0x21`), not by any CPU observable (**U-N1**).
3. **SYS_MEM rev 9 uses the OLD coreinfo masks** (`si_corerev < 12`): number of RAM banks `nb = coreinfo & 0x1F`, ROM banks `nrb = (coreinfo & 0x3E0) >> 5` [src: `G/g4389-include_sbsysmem.h:115-118`, `D/siutils.c:7038-7040`]; the `NEW_*` masks (`0xFF0000`, `0xFF000000`, `G/g4389-include_sbsysmem.h:120-123`) apply to rev >= 12 only. **brcmfmac uses a different mask for the same register** (`SRCI_SRNB_MASK 0xF0`, shift 4, `B/brcmfmac-chip.c:158-160`, `:669`); DHD is the 4389 reference, and the S35 log prints the raw word so both decodes can be checked (**U-N2**). Bank registers: `bankidx` at `0x10`, `bankinfo` at `0x40` [src: `G/g4389-include_sbsysmem.h:166-167`; struct order `asus-sbsysmem.h` fields, identical to brcmfmac's count in R37 s.4]. Closes the offset part of **U3**.
4. **The S33 SYS_MEM gate cannot stay.** The chip state is deterministic (SYS_MEM down at power-up [obs: L33]), so every `--wlan-link=N>=34` run would stop at S33 row 1339 and never reach the writes. S33 must be trimmed: remove rows 1339-1344 (the three gate rows, the window move to `0x18026000` + its read-back, the coreinfo read) and keep 1345/1346 (link logs). The SYS_MEM core page is first entered in the new S35 after the reset. Cost: the hash pin, the S33 audits/tests, `tools/s33-decode.py` (E4/E6) and `tools/test_s33_decode.py` change. The wrapper reads (rows 1329-1337) stay, so every later cumulative run re-observes the power-on state (this is also how persistence is observed, s.5).
5. **Research 37's S34 ("read-only RAM geometry") is infeasible**: it needs SYS_MEM up. This note renumbers: table step 34 = SRPWR, step 35 = SYS_MEM reset + sizing, step 36 = ARM CA7 halt ("S35" of research 37 s.9.2 = steps 34-36 together; `--wlan-link=34/35/36` give three staged runs from one table, each a strict prefix of the next).

## 2. PMU / clock / power-domain need (requirement 3)
- **ALP/HT: nothing to request.** DHD's PCIe attach and download path contains no ALP/HT request: `dhdpcie_force_alp` is defined and never called in `D/dhd_pcie.c` [obs: grep finds only the definition, `D/dhd_pcie.c:9953-9964`]; `alp_only` is only assigned (`:2146`, `:10106`, `:10349`); `ALPAVAIL` is mentioned only in the 4397A0 workaround [R37 s.2]. brcmfmac PCIe has no ALP/clkctl code [obs, R37 s.2]. The core clock comes from the wrapper `IOCTL.CLK` bit (below), the backplane runs on ALP now (SBCLKST = ALP [obs: L33]) and ALP is available. HT is NOT available (HTAVAIL 0) and DHD does not ask for it before the ARM is released (`alp_only` stays TRUE until `D/dhd_pcie.c:10349`); HT matters when the CA7 runs, outside this note.
- **SRPWR: request it, as DHD does.** Observed values cannot show whether domain 1 is on: the S33 wrapper reads returned sane values without a stall [obs: L33, closes the review-15 Medium for READS], but a read of a wrapper in an unpowered domain returning reset defaults is not excluded, and the writes are the new risk. So the order is DHD's: request, wait status, then touch the wrappers; every write has a read-back that fails the run if the write did not take (an unpowered domain would show as a read-back mismatch or a fault, both stop + restore).
  - Register: `powerctl` at offset `0x1E8` of the PCIe core (`uint32 powerctl; /* 0x1E8 */` [src: `D/include_pcie_core.h:296`], `PCIE_PWR_CTRL 0x1E8` `:1041`; "Same 0x1e8 per core" `D/siutils.c:9369`). DHD on a PCI bus reaches it at `BAR0 + 0x2000 + 0x1E8` (`si_corereg_pciefast_*`, `PCI_16KB0_PCIREGS_OFFSET 8*1024`) [src: `D/siutils.c:9283-9308`, `D/include_pcicfg.h:652`]. **We use the PCIe core page through the cfg 0x80 window instead**: cfg 0x80 := `0x18001000` (EROM-observed PCIE2 base [obs: erom-decode L33]; also the value cfg 0x80 had at power-up [obs: R36 s.0]) and BAR0+0x1E8, so no fixed-alias guess is needed. That core page + 0x1E8 is the same register DHD reaches via the alias is **[guess]** (**U-N3**); S34's first log shows plausible fields (PowerDomain id [31:28] non-zero = `si_srpwr_cap` true, `D/siutils.c:9513-9517`) if so.
  - Fields: PowerOnRequest `[11:8]` (`SRPWR_REQON_SHIFT 8`, `D/include_sbchipc.h:5199`), ExtPwrStatus `[19:16]` RO (`SRPWR_STATUS_SHIFT 16`, `:5202`), domain id `[31:28]` RO (`:5208-5209`); domain 1 = ARM/BP/SDIO, mask `1 << 1` (`SRPWR_DMN1_ARMBPSD`, `:5181-5183`). So request value `0x2 << 8 = 0x200`, status bit `0x2 << 16 = 0x20000`.
  - DHD algorithm [src: `D/siutils.c:9311-9352`]: read; if `(r & (mask<<8)) == (val<<8)` return; `r = (r & ~(mask<<8)) | (val<<8)`; write; read back; if `(r & (mask<<16)) == (val<<16)` return; else spin on status up to `PMU_MAX_TRANSITION_DLY = 15000 us` [src: `D/siutils.c:9438-9463`, `D/include_sbchipc.h:4874-4878`]. DHD never checks the register before the request and never waits on anything else (no PMU resource request).
  - Release: DHD later calls `dhd_bus_pcie_pwr_req_clear` (`D/dhd_pcie.c:780-792`). **Not in the teardown** (s.5).
- **PMU resource masks**: min_res `0x060800ED`, max_res `0x0E4FFFFF` [obs: L33]; DHD writes none of them in this path (only in the 4397A0 workaround, R37 s.2). No PMU write is planned.
- **Backplane-hang hazards**: (a) a wrapper/core write while domain 1 is off (mitigated by the status wait and the read-backs; hang signature = last usb line is the last `R35/R36` log before the first wrapper write); (b) the first read of the SYS_MEM core page `0x18026000` (never read on this chip; DHD reads `coreinfo` only after `si_iscoreup` [src: `D/siutils.c:7014-7031`]; the table enters it only after the post-reset gate rows pass); (c) a core left in `FGC` (forced clocks) by a stop between the two IOCTL writes: harmless, the chip is power-cycled by the teardown; (d) a posted store to a dead window is silently dropped (read-back catches it); (e) the CA7 running if `0x20` were not the halt bit: ARM halt is the LAST write of the last step (s.4) so everything else is logged first, and the teardown cuts the module power within seconds [guess on what a free-running boot ROM would do: **U-N1**].

## 3. The exact ordered write list (requirement 1 and 2)
Delays and waits are DHD's: `SPINWAIT(cond, 300)` = poll up to 300 us and CONTINUE on timeout [src: `D/aiutils.c:1253`]; our table stops instead (stricter). `OSL_DELAY(10)` after the reset assert [src: `D/aiutils.c:1263`]. `FGC = 0x2`, `CLOCK_EN = 0x1` [src: `D/include_hndsoc.h:266-267`]. `AIRC_RESET = 1` [src: `D/aidmp.h:372`]. Wrapper offsets IOCTL `0x408`, RESET_CTL `0x800`, RESET_ST `0x804` [src: `D/aidmp.h:168,175,176`; `B/bcma_regs.h:29,41,43`].

DHD sequence `_ai_core_reset(bits, resetbits)` [src: `D/aiutils.c:1242-1325`], with `UCM_CORRUPTION_WAR` (D11 only: `si_coreid == D11_CORE_ID`, `:1272`,`:1318`) not applicable to ARM/SYS_MEM:
1. wait RESET_ST == 0 (300 us) `:1253`; 2. **W RESET_CTL := 1** `:1262`; 3. delay 10 us `:1263`; 4. wait RESET_ST == 0 `:1266`; 5. **W IOCTL := bits | resetbits | FGC | CLK** `:1268`, read back `:1269`; 6. wait RESET_ST == 0 `:1279`; 7. loop (<= 10) `while (RESET_CTL != 0)`: wait RESET_ST == 0 `:1288`, **W RESET_CTL := 0** `:1296`, wait RESET_ST == 0 `:1299`; 8. **W IOCTL := bits | CLK** `:1313`, read back `:1315`; 9. delay 1 us `:1324`.
brcmfmac (`brcmf_chip_ai_resetcore`) reaches the same end states with the IOCTL write first (`prereset|FGC|CLK`, then RESET_CTL := 1 +10-20 us, `reset|FGC|CLK`, then RESET_CTL := 0 up to 50 times with 40-60 us sleeps, then `postreset|CLK`) [src: `B/brcmfmac-chip.c:350-382`, `:434-493`]. Order differs (IOCTL-before-reset vs reset-before-IOCTL); **DHD order is used** (4389 reference). The final IOCTL value is the same in both.

## 5. Restore story (requirement 2) and allowlist
- **Nothing is undone on the chip.** The teardown drops PERST (T20 `rc.c:3622`, `K/soc/google/gs101/wlan_seq.json:1380`) and WLAN_EN (T22 `dhd_cg.c:616`, `:1382`); WLAN_EN is the module `WL_REG_ON` (`wlan_reg_on`, `W/dhd_custom_google.c:66,529-542`). Persistence of core/SRPWR state across WLAN_EN low is **[guess]** (standard module power-off; not previously testable because no run wrote a chip register). It becomes **observed** by the next cumulative run: its S33 rows re-read the wrapper state before any S34-S36 write; IOCTL 0 / RESET_CTL 1 again = non-persistent. A teardown clear of the SRPWR request is deliberately NOT added (a write to a chip that may have just faulted; the power is cut one teardown later; DHD's clear is in `D/dhd_pcie.c:780-792`).
- **Window first**: the existing S32 teardown rows T01/T02 (cfg 0x80 := `0x18000000` + read-back, first in the teardown, `requires 32`) cover every new window: `cfg_ok` accepts `old == 0x18001000` and the other pages in a teardown row [src: `K/shim/wlanlink.c` cfg_ok, `:289-307`]; T05 later writes `0x18001000` (observed original) [src: `K/soc/google/gs101/wlan_seq.json` T05 (`wlan_seq.json:1365`)]. So cfg 0x80 returns to `0x18000000` before anything else, as research 36 s.R2 orders it (`R36:73`).
- **Allowlist (exact, new C function `memw_ok(win, off, old, v)` beside `mem_ok`; every other MEM write stays refused, `w32_blk_ok` today refuses all MEM writes `K/shim/wlanlink.c:235-238`)**, each additionally requiring the r32 guards (cfg 0x80 read live and equal to `win`, ATU1 enabled with the S29 values, Command == MEM-only, BAR0 low at the S28 assignment) and the predecessor condition read live from the SAME window:
  | win | off | old -> new | predecessor condition |
  |---|---|---|---|
  | `0x18001000` | `0x1E8` | RMW: only bit `0x200` may change, only 0 -> 1 | `old != 0xFFFFFFFF`; bits 31:28 untouched |
  | `0x18126000` / `0x18120000` | `0x800` | -> `1` ; -> `0` | `-> 1`: any; `-> 0` only if IOCTL & `0x3FFF` == `0x3` (`0x18126000`) / `0x23` (`0x18120000`) |
  | `0x18126000` | `0x408` | -> `0x3` ; -> `0x1` | `0x3` only if RESET_CTL & 1 == 1; `0x1` only if RESET_CTL & 1 == 0 and IOCTL & `0x3FFF` == `0x3` |
  | `0x18120000` | `0x408` | -> `0x23` ; -> `0x21` | `0x23` only if RESET_CTL & 1 == 1; `0x21` only if RESET_CTL & 1 == 0 and IOCTL & `0x3FFF` == `0x23` |
  | `0x18026000` | `0x10` | -> `0` | live `coreinfo != 0xFFFFFFFF`, `(coreinfo & 0x3E0) == 0` (nrb 0), `(coreinfo & 0x1F) >= 1` |
  Never: `0x400`/`0x404` (ioctrlset/clear), `0x808`/`0x80C`, any wrapper write in another window, IOCTL value with bits outside `{0x1, 0x2, 0x20}`, a 2nd wrapper (`wrapba2/3`), the PCIe/CC/D11 wrappers.
  `mem_ok` (reads) grows: `0x18001000 {0x1E8}`; `0x18126000`/`0x18120000` unchanged `{0x408,0x800,0x804}`; `0x18026000 {0x000, 0x010, 0x040}`. `cfg_ok` forward chain after the trim: `0x18126000 -> 0x18001000 -> 0x18126000 -> 0x18026000 -> 0x18120000`, each pair keyed on `old`; tighten the existing unconditional `v == 0x18001000` so a FORWARD row takes it only from `0x18126000` (today any row may, `wlanlink.c:295`).
- **Stop rules** (all end in `restore=ok`): any window read-back mismatch; SRPWR status timeout (A1); any write read-back mismatch (B1-B4, C1-C4); RESET_ST non-zero after its 300 us; RESET_CTL not clearing; B5 gate; B8 refusal (nrb != 0 or no banks); a fault on any MEM access. A bus hang cannot be stopped by a row: signature = last usb line is the last `R34/R35/R36` log before the first write of the step (the same style as U21).
- **Expected log lines** (`--wlan-link=36`, row ids [guess]): `LINK S34 start`, `R34 row=1343 rd=<powerctl>`, `R34 row=.. rd=<powerctl after, bit 17 set>`, `LINK S34 ok`, `LINK S35 start`, 3 + 3 + 1 + 3 (pre/post/gate logs) + coreinfo + bankidx + bankinfo `R35` lines, `S35 ok`, `S36 start`, 3 + 3 `R36` lines, `S36 ok`, `LINK summary reached=S36 stopped=none restore=ok`.
